## Result in one paragraph
**The board stopped publishing after 10.0 h (36,054 s uptime), not at 12 h.** Last echoed message seq 7195 at 10:17:55Z (board uptime 36,054,179 ms).
After that no new publish was sent, the MQTT process loop returned "10" (no data) from 10:18:30Z, and at 10:18:55Z (uptime 36,114 s) the TLS read failed
(`error=6 errno=5`), the firmware logged "Cleaning up TCP_TLS connection / Task stopped. Restart board to reconnect." The server logged a 60 s receive timeout
(`TCP+TLS ERROR:` with empty text, from `asyncio.wait_for(read, timeout=60)`) because no data arrived. The board did **not** crash or reboot: no panic, no boot marker, and
the free-heap line kept printing until the end (last line 10:18:14Z). As instructed, the board was not restarted; logging continued to the 12 h end (no further
messages, no reboot). **Cause not determined.** The hotspot watchdog recorded no outage (no HOTSPOT_DOWN event), but the stall onset (a few seconds after 10:17:55Z) is
not explained by the logs: the board stopped sending while its own task still ran. Possible causes (hypotheses only): short Wi-Fi/radio stall, laptop-side event, firmware loop stuck waiting on the
transport. Not investigated further.
